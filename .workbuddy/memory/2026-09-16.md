## FIN-012：完整 Compose 与 CI（DONE）

### 起点：工作区有 18 个在途文件，但探针从未被执行过

接手时 `git status` 有 `compose.yaml`/`deploy/nginx/*`/`scripts/start_stack.ps1`/
`tests/validate_nginx_proxy.ps1`/`tests/validate_one_command_up.ps1`/`ci.yml`
等在途改动（约 +1674 行）。它们语法都对、注释都很专业，但**没有一个在容器里跑过**
——上一会话 Docker daemon 没起来。所以第一件事不是提交，是把它跑起来。

### 三个真实缺陷（都是"读代码看不出来"的那类）

1. **Nginx 探针在 `nginx:1.29.3-alpine` 里调 `/usr/local/bin/python3`** ——
   该镜像根本没有 Python（实测 `command -v python3` 空）。整段 `Invoke-EntryRequest`
   是死代码。改成 `web-probe` 一次性边车（`python:3.12.14-slim-bookworm`，与
   `storage-init` 同一个 pinned digest）从 compose 网络内发请求到 `web:8080`。
   用 `compose run` 而非 `exec`（边车没有常驻进程，exec 无从附加），且**探测能力
   不进交付镜像**——web 运行时镜像仍然既无 Python 也无 curl。
2. **SSE 心跳从未真正发出**。`_RedisSubscription.wait` 里 `get_message(timeout=...)`
   在超时时**返回 `None` 而不是抛异常**，所以 `wait` 无法区分「被唤醒」与「到点」，
   `service.py` 的 `except TimeoutError` 永远不触发 ⇒ 长连接上除首批重放外没有任何帧。
   把 `Subscription.wait` 的返回类型改成 `bool`（超时 `False`、被唤醒 `True`），
   `service.py` 改为 `if not woke: yield format_heartbeat()`。
   `tests/unit/test_sse.py` 新增 2 项不变量守住它。
3. **`check_probe_python.ps1` 自己无法解析**：替换表写成
   `[ordered] @{ '$Token' = ...; '$token' = ... }`，而**哈希表键大小写不敏感**，
   两项撞成重复键 ⇒ 解析错误。改成键值对数组（顺序也因此显式化）。
   讽刺的是这个脚本的用途正是"校验别人脚本能解析"。

### 环境坑（本机，别再踩）

- **Windows PowerShell 5.1 宿主不维护 `$LASTEXITCODE`**：实测 `& docker bogus-arg`
  之后仍是 0（甚至从未赋值，StrictMode 下读取直接抛错）。所以**本机无法运行任何
  依赖退出码的探针**，包括 `start_stack.ps1`、`validate_*.ps1`。CI 用 pwsh 7 正常。
  本机没有 pwsh、没有 winget。
  应对：本机做静态门禁（`scripts/check_powershell_syntax.ps1`，`[Parser]::ParseInput`）
  + 用 Bash 手工驱动等价流程；容器级运行时验证交 CI。
- **compose 插件不在 PATH**：`docker compose` 报 unknown command。插件在
  `C:\Program Files\Docker\cli-plugins\docker-compose.exe`，复制到
  `~/.docker/cli-plugins/` 后可用（v5.4.0）。
- **端口 5433/6380/8000 被遗留的 `fin012-verify` 项目占着**，跑自己的栈要显式设
  `POSTGRES_HOST_PORT`/`REDIS_HOST_PORT`/`API_HOST_PORT`/`WEB_HOST_PORT`。
- Docker Desktop 装在 `D:\develop\Docker`，启动器是 `./Docker Desktop.exe`。
