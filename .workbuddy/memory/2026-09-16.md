## FIN-013 收口：CI 全红的三层根因修完，e2e 首度全绿

`validate_web.ps1` 的 18 条 Playwright 在 CI 上 15/18 failed。三层根因**互不相关**，
逐层剥开（操作级细节在 `PITFALLS.md`）：

1. **连接池被 SSE 流耗尽** —— `/events` 的依赖是 async generator，它开的 session
   只在响应结束时才关（= run 终态或浏览器离开），于是每条活流钉死一条池化连接。
   8 条并发流吃光 5+10 的池，此后**同进程所有路由**（含登录）等满 `DB_POOL_TIMEOUT`
   再回裸 500。`SqlAgentRunRepository` 自己管短会话且每次 poll 释放快照，所以流本身
   和授权闭包都不需要流级 session —— 授权改成每次检查开一条短会话。另把
   `sqlalchemy.exc.TimeoutError` 映射为 503 + `Retry-After`。
2. **404 撤权被读成撕裂的响应体** —— `get_authorized` 表达「无权可见」用的是 404
   （`JOB_NOT_FOUND`），不是 403，§12 两者都认可。但流的 `AppError` 白名单只认
   401/403，于是中途撤权走 404 时流直接断，浏览器只看到裸 EOF → 重连 → 再被拒，
   变成无限重连而不是 §13.4 要求的单帧 `SSE_AUTH_REVOKED`。白名单补 404。
3. **`classifySequence` 把首帧误判成跳号**（真正的 killer）—— 服务端

### ⛔ 更正旧结论：pwsh 7.6.6 **能**在工具会话里真跑项目门禁

此前记的「工具会话拉不起子进程，pwsh 只能留给兰骐手动用」是**错的**。
正解是把内层逻辑写成纯 ASCII 的 runner `.ps1`，再用完整路径调：

```

  Out-File <log> -Encoding utf8   # 然后 Read 那个 log
```

两个必踩的坑：

1. **别用 `-Command`**：双引号会被外层 PS 5.1 的实参传递剥掉，`"NONSEED_ERROR=$($_.Exception.Message)"`
   变成裸命令名直接报错，而 `"NONSEED_EXIT=1"` 恰好能活 —— 让人误以为引号没问题。
2. **子进程 pwsh 的 `[Console]::OutputEncoding` 继承父会话 = gb2312**。docker 的 UTF-8 输出

   **CI（utf-8）不受影响，所以这是「本机红、CI 绿」**，排查时容易怀疑探针本身。
3. `$Args` 是 PowerShell 自动变量，把它当函数参数名会让 `git @Args` 静默退化成裸 `git`
   （每次调用都打印 git 用法，exit 1，什么都不做）。
4. **Edit 工具会丢掉 `.ps1` 的 UTF-8 BOM**（HEAD 有 `EF BB BF`、改完没有）。补回：
   `[IO.File]::WriteAllText($p,$t,(New-Object Text.UTF8Encoding($true)))`。

  - `GET /match-runs/{id}/events` → **503，duration 30008ms**（两次）
  - `POST /applications/{id}/runs` → **503，duration 30002ms**（就是 fin011 点「启动单人流程」那个）

503 是上一轮新加的 `core/errors.py::handle_pool_exhausted`（池超时 → 503 + `Retry-After: 1`），
所以**池耗尽根本没修好，只是把 500 换成了 503**，而 503 让症状变得更难辨认。

### 真根因：`yield` 挂起时生成器无法归还连接

`sse/service.py::SseService.stream` 原来在**事务开着的时候 yield 帧**（`list_events_after`
之后直接 `for event in events: yield format_event(event)`）。生成器一挂在 `yield` 上，控制权
就交给 ASGI 层去写 socket，**生成器内部什么都不跑**，所以它没法执行 rollback —— 浏览器卡顿、
导航走开、重连待定期，那条连接就永久 `idle in transaction`。14 条这样的流足以清空池。

第二个更隐蔽的缝：`resolve_initial` 借的连接原本要到流的第一轮循环才还，而
`stream` 的**第一个 `yield format_retry` 在循环之前**。客户端若在 header 与首块 body 之间
消失，生成器**从未被进入** → `finally` 永不执行 → 连接彻底丢失。

**修法**（三处，都在「任何 yield 之前先还连接」这一个原则上）：
1. 在事务内把帧**渲染成字符串**（`format_event` 是纯函数、无 IO），`refresh_for_poll()` 结束
   事务，**再** yield 那些字符串。注意 `refresh_for_poll` 会 `expire_all()`，所以
   `run.status` / `run.config_snapshot_json` 这类 ORM 属性必须在 rollback **之前**读完
   （否则 rollback 后的访问会懒加载，把连接又拉回来）。
2. `resolve_initial` 正常返回前也 `refresh_for_poll()`（不只是异常路径 `aclose`）。
3. `except AppError` 走 `SSE_AUTH_REVOKED` 之前同样先归还。

### 守卫测试：把「连接是否被占」变成可断言的状态

`_PoolTrackingRepository` 用 `holding` 布尔标记模拟「事务未结束＝连接被占」（读操作置位、
`refresh_for_poll` 清位），于是循环的调用位置从测试里可观测。新增两条：

- `test_frames_are_yielded_without_a_pooled_connection` —— 逐次 `__anext__`，每次返回时检查
  `holding`。**旧代码下 `held=[False, True, True]`**（事件帧与心跳帧都在持有连接时 yield）。
- `test_initial_resolution_releases_its_connection` —— 握手成功返回后 `holding is False`
  且 `aclosed is False`（还债靠 rollback，不是把流要复用的 session 关掉）。

两条都用 copy-based 回滚验证过：把 HEAD 版 `service.py` 拷进 `/tmp/old` 覆盖，两条都 FAIL。

4. **查库**：`select run_id,min(sequence)… group by run_id` → 每条 run 都是 **1..N**。

### 根因

`apps/web/src/api/sse.ts` 的 `classifySequence`：`lastAccepted` 初值 `-1` 语义是「无游标」，
但判据写成 `sequence > lastAccepted + 1` → `classifySequence(1, -1)` = `1 > 0` = **gap**。
首帧必判跳号 → `abandonStream()` → `reconnectFrom(-1)`（仍无游标，重连不带
`Last-Event-ID`）→ 服务端重放同一帧 → 再判 gap → **死循环**。
修：`if (lastAccepted >= 0 && sequence > lastAccepted + 1) return "gap"`。

**迷惑点（记下来，下次先查这个）**：最终错误文案取决于**谁抢到最后一次 `onError`**，
实测是撤权后重连撞上的 404，于是「流程或所属岗位不可见」把它伪装成撤权问题。
我因此在 `sse.py` 404 白名单 / `RunTimeline` 提示 / seed `hm.demo` 上绕了一大圈 —— 那些
改动各自都是对的（也确实补掉了真实缺陷），但都不是这条红的原因。**先看时间线有没有
渲染出事件，别先看错误文案。**

### 测试为什么三层都没抓住

- 单测 fixture 一直从 `sequence 0` 起，而服务端**从不发 0**（已全线改 1 起，并在
  `event()` helper 上写明原因）；
- e2e 注入帧同样 0 起；
- 「真实流」用例只断言 `实时同步`，那是 `onOpen` 就出现的连接态，与事件内容无关。

补救：`classifySequence(1, -1) === "accept"` 单测 + 一条 connect 级回归
（`starts a fresh subscription at sequence 1 instead of looping on a phantom gap`）
+ 真实撤权用例里断言时间线 `toContainText("#1")`。

### 回退验证踩的坑：这类回归是 **OOM** 而不是失败

改完再回退验证：**7 failed / 10 passed，13 秒干净失败**，且失败信息里能看到
